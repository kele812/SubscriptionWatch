# SubscriptionWatch v4.0.18

每个面板的“插件接入”可保存最多5个指向同一风控机的 HTTPS 地址，按优先顺序排列。保存后，还需在 Xboard 采集插件中用英文逗号填写同一组地址，并在 XBnpp 节点上配置备用地址。连接失败、超时或服务器5xx时才切换；认证失败、签名错误不切换。所有地址不可用时，由插件的“风控后台失联时继续下发”开关决定是否下发，默认关闭（拒绝）。

## 上传插件

后台和采集插件统一为 **v4.0.18**。下载 [后台 ZIP](https://github.com/kele812/SubscriptionWatch/raw/refs/heads/main/downloads/SubscriptionWatch-v4.0.18.zip) 和 [采集插件 ZIP](https://github.com/kele812/SubscriptionWatch/raw/refs/heads/main/downloads/SubscriptionWatchCollector-v4.0.18.zip)。先更新风控后台，再在 Xboard 插件管理上传新版插件并启用。访问记录同时展示“结果”（这次请求）和“当前状态”（该用户现在是否可疑、是否达到24小时请求上限，以及已计入次数和下一次序号）；本次请求通过 IP／域名白名单订阅时，列表和详情会单独标注，当前状态仍显示近24小时白名单次数。升级时能从留存的审核结果补标旧记录；找不到审核结果的旧记录不猜测。可在该行单独重置用户24小时计数，访问历史和可疑标记保留。同一次请求会检查完所有适用规则，访问详情逐条列出本次拦截原因；用户及 IP／域名白名单仍优先豁免所有规则；Cloudflare 豁免按下述新范围执行。

访问记录的“结果”栏已加宽：规则拦截时逐条列出命中规则；请求失败时显示能确认的原因。新版插件会用固定类别上报风控审核失联、响应校验失败等插件拒绝原因，不上传错误正文。其他失败只按响应状态、内容类型和是否返回订阅解释；若证据不足，则明确显示“具体原因未记录”。旧记录不会被推断为某种插件故障。

风险规则按面板新增“可疑用户禁止获取订阅”开关，默认开启；关闭只放行已有可疑标记这一项，其余规则照常执行。后台“访问记录”已更名为“获取订阅记录”。风险规则有独立菜单。可按面板开启“仅允许中国大陆或白名单 IP 获取订阅”；白名单支持 IP、域名和备注，域名解析失败时不匹配。严格执行地域限制时，插件的“风控后台失联时继续下发”须保持关闭。用户白名单或 IP／域名白名单命中后，跳过所有订阅风控规则，包括每日次数和已有可疑标记；访问仍记录。未命中白名单的大陆来源仍按其他规则检查。非指定客户端只拦截本次订阅，不标记可疑；多个中国大陆或非中国大陆 IP 在达到阈值的当次标记并跳转；云服务器 IP 每次请求都跳转，60 分钟第 3 次或 720 分钟第 10 次标记可疑。黑名单命中可选择启用拦截。每个用户滚动 24 小时默认最多请求 30 次，第 31 次起跳转，成功和拦截都计数；上限本身不标记可疑。手动取消可疑标记后，该用户每日次数从零重新计算，旧访问记录保留。风控后台失联或审核超时时，插件默认拒绝本次订阅；手动开启失联放行后才继续下发。后台明确拒绝、密钥错误或验签失败始终拒绝。

先在风控后台添加面板，再把风控 HTTPS 地址、面板标识和采集密钥填入插件。可信代理 IP 只填写你实际使用的反代 IP；Xboard 原有的每分钟计划任务需正常运行。

要区分客户来源 IP 与经过的反代，在每台反代的 Nginx `location /` 内覆盖这两个请求头，并填写该反代自己的公网 IP 和名称：

```nginx
proxy_set_header X-Watch-Proxy-IP "反代公网IP";
proxy_set_header X-Watch-Proxy-Name "自定义反代名称";
```

插件只在该 IP 确实出现在本次请求的可信转发链中时记录反代名称。直连或链路未核对成功时显示“未记录外部反代”；升级前的历史反代标识显示“未核实”。反代 IP 和名称由各台反代自行填写，不在程序中固定。

## 一键部署

在 Ubuntu 风控 VPS 上以 root 执行，先安装 Git、Docker 和 Docker Compose。下面命令下载代码、构建并启动服务，目标目录需尚不存在：

```bash
git clone https://github.com/kele812/SubscriptionWatch.git /opt/SubscriptionWatch-repo && bash /opt/SubscriptionWatch-repo/deploy.sh
```

## 一键更新

下载最新版、备份数据并重启风控后台：

```bash
bash /opt/SubscriptionWatch-repo/update.sh
```

原账号和数据保留，备份在 `/opt/SubscriptionWatch-backup-*`。采集插件需在 Xboard 单独上传更新。如果旧安装使用 SSH 下载，先执行：

```bash
git -C /opt/SubscriptionWatch-repo remote set-url origin https://github.com/kele812/SubscriptionWatch.git
```

## 宝塔反代

1. 将域名解析到风控 VPS，在宝塔添加此域名的网站。
2. 为网站申请 SSL，启用 HTTPS。
3. 添加反向代理，目标地址填 `http://127.0.0.1:18080`，关闭代理缓存。
4. 浏览器打开 `https://你的域名`，首次访问创建账号密码，再添加 Xboard 面板并配置插件。


## 4.0.16 Cloudflare 豁免调整

开启 Cloudflare 豁免后，仅对客户来源 IP 归属机构为 Cloudflare 的请求跳过地区限制、已有可疑标记、云服务器、黑名单及多 IP 阈值检查；仍执行已启用的 UA 检查和滚动24小时次数上限，成功与规则拦截均登记计数。已有可疑标记不被清除，历史记录不改写；网站套 Cloudflare 不等于客户 IP 命中豁免。用户及 IP／域名白名单仍优先豁免所有规则。


## 4.0.17 指定客户订阅地址

在风控后台左侧进入“修改订阅的用户”，选择对应面板，点击“新增指定订阅地址”，填写 Xboard 客户 ID、准确邮箱和 HTTPS 根地址，例如 https://sub.example.com。未产生采集记录的客户也可预先设置；已采集客户需与当前邮箱一致。列表支持按 ID、邮箱或域名搜索和分页，显示修改时间、插件最近查询及状态，可继续编辑或恢复默认。恢复默认后仍保留这名客户的修改记录。

插件接入 Xboard 官方 subscribe.url 过滤器：客户刷新 Xboard 的订阅信息后，“复制订阅”和“一键导入”使用指定地址。只替换原链接的协议/域名/端口，原订阅路径、Token 与查询参数原样保留；订阅 Token 只在 Xboard 本地使用，不上传风控后台、不由后台另行生成。设置按面板、客户 ID 与邮箱隔离；用户变更邮箱后需核对并编辑设置。

填写的域名必须已配置 HTTPS，且能转发至同一套 Xboard。这里只管理对外展示的订阅根地址，不会自动配置 DNS、Cloudflare、证书或反向代理，不改变原有订阅审核规则，也不会禁用已经发出去的旧域名。已导入客户端的旧链接不会自动替换，客户需重新复制/导入；网页若保留旧订阅信息，也需刷新。

地址查询采用独立 HMAC 请求/响应签名、短时效和随机 nonce 校验，不走每分钟轮询，每个新请求实时查询；只在同一次请求内去重，不跨客户或跨请求缓存。查询超时、风控离线、配置不完整或响应不可信时，保持 Xboard 原来生成的站点默认地址，以免阻断客户页面；这不等于订阅审核失联放行，后续订阅请求仍执行既有审核策略。列表“插件已查询”不代表客户已导入成功。

升级顺序：先升级后台至 4.0.17，再上传并启用 4.0.17 采集插件。4.0.18 同时接入链接生成钩子和标准用户/管理员 JSON 响应兼容，无需修改 Xboard 核心代码或数据库；非标准 API 或定制主题仍需核对。首次启动后台自动创建独立地址表，原账户和数据保留；完整数据库备份包含这些设置。


## 4.0.18 修复订阅地址未生效

4.0.17 仅从查询参数 token 识别客户，漏掉了当前 Xboard 默认的 /s/{token}（以及自定义订阅路径）格式，导致插件直接返回旧链接，风控一直显示“待客户刷新订阅信息”。4.0.18 同时支持路径末尾 Token 和旧版 ?token= 格式；保留原路径、Token 和其他参数，不重置客户 Token/UUID。

除 subscribe.url 过滤器外，增加 RequestHandled 响应兼容：只处理标准 api/v1、api/v2 用户订阅信息和管理员用户列表/用户详情等成功 JSON 响应中的 subscribe_url 字段，以及 resetSecurity 已生成的链接结果。不会主动调用重置操作，不改其他字段、分页元数据、HTML、节点订阅内容或错误响应。按真实 Token 所属用户查询，后台可继续按面板/ID/邮箱隔离。处理后的订阅信息响应禁用缓存。

风控中的旧设置原样保留；首次启动自动补充诊断字段。未查询状态改为“尚未成功查询”；签名查询到达但邮箱不符时显示“查询邮箱不匹配，未应用”。Xboard 日志以固定前缀 Subscription Watch subscription URL lookup failed 记录 code 和 user_id，不记录原链接、Token、密钥、响应正文或异常原文。常见 code：unavailable（连接失败/超时）、http-401/403/404（认证/拒绝/接口不存在）、response-signature-invalid（验签异常）、response-invalid-or-expired（身份/时效校验失败）、email-mismatch（邮箱不匹配）。同一请求第一次发现后台不可用后，不再对管理员列表每个客户重复等待；下个请求重新尝试。

升级顺序：

1. 在风控 VPS 执行 bash /opt/SubscriptionWatch-repo/update.sh，升级后台。
2. 在 Xboard 上传并启用 4.0.18 采集插件。
3. 在 **Xboard 自己的项目目录**（含其 compose.yaml 的目录，不是风控后台目录）执行 docker compose restart，使 Octane/常驻 PHP 进程加载新插件文件；这会短暂重启该 Compose 项目的服务。
4. 刷新 Xboard 管理员用户列表或客户订阅信息，复制链接检查域名，再查看风控是否变为“插件已查询”。已有设置无需重新添加，客户端中已导入的旧链接需重新导入。

若仍未生效，先核对 Xboard 日志中的固定 code，以及是否使用了非标准 API 路径或不读取 subscribe_url 的自定义主题；不要提供完整订阅链接、Token 或密钥。此修复已用官方默认路径式链接及旧查询式链接验证，并未直接连接你的线上面板。


## 4.0.18 备选订阅地址

在“修改订阅的用户”页面展开“备选订阅地址”，每行填写一个 HTTPS 根地址，最多20个，点击“保存备选地址”。列表按面板独立保存、规范化并去重。首次未保存列表时，自动提供本面板已指定过的地址，减少重复输入。

新增或编辑客户时，使用“选择订阅地址”下拉框；需要临时地址时选择“手动输入其他地址”。若客户当前地址已不在备选列表中，仍会保留并默认选中该地址，不会因打开编辑弹窗而被替换。

备选列表不做自动轮换，修改/移除备选项不会批量改变客户已指定的地址；只有保存某个客户的设置才改变该客户的新订阅链接。清空备选列表后仍可手动输入。保存含并发版本校验，遇到列表已变化时点击页面“刷新”后重新编辑。地址设置和备选列表均随数据库备份、重启保留。
