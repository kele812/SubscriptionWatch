# v4.0.24：订阅设备限制

本版本新增订阅设备限制；默认关闭。先升级后台与插件，再按需开启，不自动修改线上规则。

## 升级与开启

1. 备份现有风控数据，先升级风控后台至本包 4.0.24。保留原 Compose 项目及数据卷，使用新源码重新构建服务；不要创建空数据卷替代旧数据。
2. Xboard 上传并启用配套 SubscriptionWatchCollector 4.0.24，然后重启其常驻服务，使新插件生效。新插件要求新版风控返回设备策略能力标记，连接旧风控会拒绝审核，不要颠倒升级顺序。
3. Android、Windows 使用 Pa55Wall 1.0.30。macOS 共用同一设备编号逻辑，使用安全存储的安装编号，但本机未编译、实测 macOS 版本。
4. 在风控左侧独立的“设备管理”分组中设置占用时长（默认 24 小时，支持 1～8760 整小时），保存并开启“启用订阅设备数量限制”。每个面板独立，升级默认关闭，不自动对现有客户生效。
5. 严格限制时，采集插件的“风控后台失联时继续下发”保持关闭。该原有开关若开启，风控失联时可能继续下发订阅。

## 规则

- 上限直接读取本次 Xboard 认证用户的 `device_limit`，由插件签名传给风控；null、0 表示不限数量。客户端不能自行声明上限。
- Pa55Wall Android、Windows、macOS 使用 `X-HWID`。编号与账号、客户端版本、出口 IP 无关；普通与 Meta 格式请求使用相同编号。Android 使用系统 ANDROID_ID 的应用摘要；Windows 使用 MachineGuid 的应用摘要。首次生成后保存在安全存储中；系统标识不可用时使用安全随机安装编号。设置恢复默认、账号退出、配置导出不清除此编号。
- iPhone/iPad 的 Shadowrocket 按完整原始 UA 识别，忽略其 HWID，不要求用户开启“发送 HWID”。同 UA 会合并为一席；客户端或系统升级使 UA 改变，可能新增一席。这是用户指定的识别口径，无法准确区分 UA 完全相同的物理设备。
- 所有识别方式共用账号额度，按面板、用户及当前邮箱隔离。同设备重复请求只占一席。额度满时拒绝新设备，已有设备仍可刷新；Xboard 下调上限不主动踢出已经登记的设备。
- 用户白名单不受设备上限、设备编号检查影响；IP/域名及专用导入链接白名单只保留原有风险规则豁免，不能绕过设备额度。
- 开启设备限制后仍检查所有原有风险规则，并列出本次能确认的全部命中原因。关闭只跳过设备检查，不关闭原有风控。
- 成功下发后才续期，从最后成功下发时间计算占用时长；失败不续期。并发请求先预留名额防止抢占，待本次结果确认；结果未送达时预留最多 5 分钟，迟到结果不能在清除或预留失效后重建名额。
- 设备管理可按用户 ID/邮箱查询，显示识别方式、系统、指纹、最近成功时间、预计释放时间和设备上限快照。支持清除指定用户全部设备，或确认后清除当前面板全部设备；不会影响其他面板。

## 仅随订阅请求上报

每次获取订阅时最多一次风控审核和一次结果上报。插件只读取本次认证用户已有字段，不扫描客户列表、不开设备定时轮询。审核总预算 4 秒；结果上报总预算 1 秒，备用风控地址共享预算。

当前结果优先立即发送，结果上报失败才写入原有有界 Redis 临时队列；后续客户获取订阅时，顺带补传最多 99 条旧结果。无客户请求时不上传订阅记录，也不为此唤醒 Xboard。排队、过期或 Redis/网络故障可能丢失结果，未确认成功不续期。这里的“成功下发”表示 Xboard 已生成成功响应，不能证明手机实际下载、解析完成。

原有订阅地址配置同步和封禁任务领取保留独立调度，不属于订阅设备轮询或订阅记录上报。风控自身清理过期本地记录不请求 Xboard。

“获取订阅记录”首页直接展示 403 设备拒绝及其他规则拦截原因；设备超限保存当次占用数量/上限。已知插件故障、空响应、网页响应与普通 HTTP 失败分别说明，证据不足时明确显示具体原因未记录，不推测。新插件按请求上报的健康状态不再因为无访问超过三分钟就误报上报中断。

## 验证与边界

风控完整 Node 回归 74/74（含 PHP→本机后台签名调用）通过；设备元数据 9 项、按请求报告 9 项 PHP 检查通过；全部插件 PHP 语法通过。客户端 315 项通过，1 项平台跳过；lib/test 严格分析无问题。Android 正式签名及 16 KiB 对齐校验、Windows 发布包核对通过。浏览器已验证独立设备分组、时长保存和清除确认；未进行真实手机/Xboard 线上联调、macOS 编译或 Docker 部署。

本功能控制获取新订阅，不撤销已保存的节点。HWID 和 UA 都由客户端请求提供，可被仿造；不是硬件可信认证。应用重装、系统重装、分身、虚拟机克隆等可能改变或复制身份，管理员可清除名额。

## v4.0.25 · 获取订阅记录显示当前设备数量

“获取订阅记录”新增“当前设备数量”列，记录详情同步显示。同一用户的所有历史行都显示查询时的最新有效占用，不是当次请求的历史快照，也不表示在线设备。按当前面板、用户ID及当前邮箱隔离，排除过期设备，同一指纹去重；未过期预留占用包含在总数中并单独注明。清除设备后刷新列表即可看到新数量。

设备限制未开启且没有登记记录时显示“未开启”；用户白名单没有登记设备时显示“白名单免限（未登记）”；缺少已核实用户资料时显示“未记录”。关闭限制但仍有有效登记时保留数量并注明限制已关闭。不会根据IP或UA历史行数猜测设备数量。

每页设备数由风控本地数据库一次批量查询取得，不逐用户访问Xboard。已有4.0.24采集插件继续兼容，本次更新后台并刷新浏览器即可；新后台和插件安装包统一4.0.25。原设备限制、专用链接和订阅请求审核规则保持。

在获取订阅记录的“当前设备数量”旁点击“管理设备”，会切换到当前面板的设备管理页，自动填入这名用户的ID并从第1页查询。纯数字查询精确匹配用户ID，防止其他账号邮箱包含同样数字时混入结果；邮箱文字查询仍支持模糊搜索。
