# 订阅观察采集器 v4.0.23

安装在 Xboard，配合独立风控后台 v4.0.22。先升级后台再更新插件。“风控后台地址”可用英文逗号填写最多5个指向同一风控机的 HTTPS 域名，按顺序切换；后台页面保存的地址不会自动同步到插件。连接失败、超时或服务器5xx才试下一个；认证失败和签名错误直接拒绝。所有地址都不可用时，由“风控后台失联时继续下发”开关决定是否下发，默认关闭（拒绝）。要在风控记录中显示经过的反代，需在反代的 Nginx `location /` 中覆盖 `X-Watch-Proxy-IP` 和 `X-Watch-Proxy-Name` 请求头，分别填写该反代的公网 IP 和名称。

插件只记录实际出现在可信转发链中的外部反代 IP；不能核对时不记录反代名称。IP 和名称由每台反代配置，没有写死在插件中。

v4.0.14 起，插件拒绝本次订阅时会向风控后台上报固定失败类别，用于访问记录显示风控审核失联或校验失败等原因；不上传异常原文或订阅响应正文。旧访问记录不能补出这些类别。

## 安装和更新

Xboard 插件管理上传 ZIP 安装或更新，填写风控 HTTPS 根地址、面板标识、采集密钥并启用。更新沿用原配置，不需要管理 API Authorization；不同 Xboard 不共用面板标识。

可信代理 IP 按实际链路填写。填写将请求转发给 Xboard 的反向代理实际 IP；本机 Nginx 或 Docker 网关也按实际连接 IP 填写，多个用英文逗号分隔。没有代理则留空，不填客户 IP 或普通节点出口 IP。仅信任自己控制的代理。

沿用已有每分钟 Laravel scheduler，不重复添加计划任务；Octane 按原部署方式重载。约 1～2 分钟后后台显示插件通道已连接，自动封禁默认关闭，需手动开启。

## 采集与开销

通过 client.subscribe.before 和 Laravel RequestHandled 采集已认证用户 ID、邮箱、IP、原始 UA、响应状态、请求编号、内容类型和订阅 Token 的 HMAC 指纹，写入独立前缀 Redis 缓冲。不存原始订阅 Token、节点配置或响应正文，不建立数据库表，不修改核心代码。插件配置和安装状态仍由 Xboard 保存。

订阅请求会同步等待风控机审核，请求超时上限4秒。规则触发拦截时，插件按后台签名的跳转地址返回 302，不下发订阅内容。所有风控地址连接失败、超时或返回服务器5xx时，“风控后台失联时继续下发”开关开启才照常下发，关闭则只拒绝本次请求；默认为关闭。风控后台明确拒绝、密钥错误、验签失败或插件配置错误始终拒绝。每分钟最多上报 3 批访问记录、每批 100 条。默认缓冲 2000 条、有效期 1 小时；队列满、过期和 Redis 故障可能丢记录。Redis RDB/AOF 可能持久化临时数据。

## 可选封禁

每分钟采集上报后最多领取 3 条封禁任务。使用原采集密钥对请求和响应签名，绑定面板及随机请求标识，任务有效期 30 秒，无需新开 Xboard 控制端口。

风险由风控机评估。插件支持封禁与明确提交的手动解封，事务内核对 ID、邮箱、期限和管理员/员工身份，设置 banned=1 并调用 Xboard 会话清理服务，失败回滚。不改数据库结构；其他用户字段保持原值，ORM 可能更新修改时间。

执行前通过 Redis 去重并保存回执，Redis 不可用时不执行。回执最多 100 条、保留 7 天，重传直到后台确认。后台只下发一次，执行失败或结果丢失显示“失败或待核对”，需人工核对 Xboard，不自动重新执行该任务。

关闭开关不会撤回已领取且未过期的任务；风险解除或加入白名单不会自动解封；手动解封任务仅修改banned=0。更换面板归属或密钥前先处理原缓冲和待确认任务，避免记录错归或回执遗失。

风险计算、IP 数据库、历史和 TG 全在风控机。Xboard 有少量采集、每分钟网络请求及封禁必要操作开销，不是零开销。普通采集不写用户业务表；实际封禁会修改用户状态并删除登录会话。

## 验证

PHP 8.2 语法解析及 PHP 8.5 模拟 Xboard/Redis/HTTP 执行测试通过，覆盖签名、隔离、重复任务、身份检查及回滚。真实 Xboard/Octane/Redis 仍需使用测试账号验收。

新增上报失败计数（Redis可用时记录、七天过期）；通过ban-v2能力标识支持手动解封，仍每分钟最多三个控制任务。自动封禁默认关闭，风控机按当前证据门槛判断，不设观察等待期。


## 4.0.16 Cloudflare 豁免调整

开启 Cloudflare 豁免后，仅对客户来源 IP 归属机构为 Cloudflare 的请求跳过地区限制、已有可疑标记、云服务器、黑名单及多 IP 阈值检查；仍执行已启用的 UA 检查和滚动24小时次数上限，成功与规则拦截均登记计数。已有可疑标记不被清除，历史记录不改写；网站套 Cloudflare 不等于客户 IP 命中豁免。用户及 IP／域名白名单仍优先豁免所有规则。



## 4.0.22 指定订阅地址与本地同步

在左侧“修改订阅的用户”页面，先填写安装了插件的 Xboard HTTPS 根地址，点击“保存地址并立即同步”。风控服务器须能访问该地址；Cloudflare/WAF 不应向 /api/v1/guest/subscription-watch/origin-sync 和 origin-lookup 返回浏览器挑战。两端使用已有采集密钥验签，不需要远程 MySQL 密码。

输入完整客户 ID 或邮箱点击搜索，显示 Xboard 当前生成的完整订阅地址，并可直接修改。链接包含客户 Token，仅在已登录管理页面按需返回，不保存到风控数据库、采集或诊断日志。自动刷新和读取已修改列表不会远程查询客户。主题需读取标准 subscribe_url，无需修改复制按钮。

搜索后修改与手动新增共用一条设置：同面板同客户 ID 以最后一次保存为准，搜索本身不修改。已采集邮箱须匹配。备选地址按面板独立保存，最多20个；编辑时可选择或手输。单独的“已修改用户”列表保留客户、指定域名、同步状态和修改时间，支持编辑和删除。

保存或删除会立即发签名通知。插件拉取分页快照，事务写入 Xboard 本地 subscription_watch_origins、subscription_watch_origin_state 独立表，再返回签名确认。显示“已同步到 Xboard”才表示已确认；失败时显示待同步，风控保留新设置，Xboard保留最近完整配置，每分钟任务补同步。未配置 Xboard 地址时仅定时同步，搜索不可用。同步不是无等待的保证，主动通知超时后仍可能由后续调度完成。

生成链接只读本地数据，同一请求一次映射查询，无逐客户远程地址请求。以本地用户ID、邮箱匹配当前Token，只替换根地址并保留路径参数。首次同步前或本地表不可读时使用站点默认地址；风控失联后保留最近同步地址。实际客户端订阅请求的风控审核和失联策略不变。

删除从已修改列表移除，同步成功后清除本地设置、恢复默认，不删除客户或备选地址。删除同步失败时旧映射暂存，可点击“保存地址并立即同步”重试。旧版已恢复默认记录也能删除。

先升级后台，再上传启用4.0.22插件，在 Xboard 自己的 Compose 项目目录执行 docker compose restart，使常驻进程加载新插件和路由。配置 Xboard 地址并同步，原指定客户自动迁入，无需重加。同步后刷新Xboard管理员或客户页面再复制／导入；客户端旧链接需重新导入。指定域名仍需提前配置同一Xboard的DNS、HTTPS、反代。不要回退旧插件，否则恢复逐客户网络查询。本次未连接你的线上Xboard，不保证其他原因的卡顿同时消失。

## 4.0.22 HTTP 地址与错误提示

备选和客户指定订阅地址均支持 HTTP / HTTPS 根地址，可带端口，例如 http://sub.example.com:8080。仍拒绝账号密码、路径、查询参数、Token 和其他协议；保存备选后可下拉选择并同步到 Xboard 本地，协议和端口保留。

填写错误、请求失败与未确认的主动同步显示红色提示；成功提示保留绿色，编辑弹窗内错误也为红色。Xboard 管理同步地址以及插件连接风控后台的地址仍使用 HTTPS。先更新后台，再更新4.0.22插件并重启Xboard常驻进程，保证HTTP配置可以完整同步。

## 4.0.22 获取并复制客户订阅地址

在“修改订阅的用户”中按完整客户ID或邮箱搜索，结果显示可选中的完整订阅地址，点击“复制订阅地址”可直接复制。已修改用户每行新增“获取订阅地址”和“复制订阅地址”。每次复制前重新查询Xboard当前链接，保留协议、端口、路径、Token和参数；不会用指定根域名自行拼出链接。

修改并同步成功后自动重新获取地址，可直接复制；待同步时不把旧查询结果显示成新地址。获取失败会明确提示可重试，不把已保存的修改误报成保存失败。切换面板、切换页面或再次修改时清除旧结果，丢弃迟到响应。浏览器不允许自动复制时可选中地址手动复制，不误报复制成功。

获取完整URL只在搜索、获取、复制以及本次成功修改后按需进行，普通刷新和列表加载不逐客户远程查询。完整链接仅保存在当前页面，不写入风控数据库、浏览器持久存储或日志。需要配置Xboard HTTPS根地址并启用支持查询的插件。版本统一4.0.22，更新后台及插件并重启Xboard服务；不重置客户Token。

## v4.0.22 · Shadowrocket 专用导入页

在“修改订阅的用户”中搜索客户，或在已修改用户的操作栏点击“Shadowrocket 导入页”，复制分享链接发给客户。链接长期有效，重复打开操作会复用原链接，可在弹窗中手动撤销。分享地址使用当前打开风控后台的域名，请使用客户可以访问的公开 HTTPS 地址；反向代理需放行 `/sr-import/` 和 `/shadowrocket-import.js`，不要只转发管理 API。

客户用 Safari 或其他浏览器打开，点击“导入到 Shadowrocket”唤起已安装的应用；iOS 可能要求确认。微信、QQ 内置浏览器会显示“请用其他浏览器打开”，不获取或展示订阅内容；独立 QQ 浏览器不会仅因 MQQBrowser 标识被误拦。检测依赖浏览器 UA，只用于提示。导入协议采用标准 Base64，参考 [3x-ui 的实现](https://github.com/MHSanaei/3x-ui/blob/c58db81/frontend/src/pages/sub/SubPage.tsx)。尚未进行真实 iPhone / Shadowrocket 安装环境测试。

**白名单仅适用于通过这个页面获得、带专用凭证的订阅请求。** 后台仍核对面板、客户 ID 和邮箱；插件上报签名后的凭证指纹，不能凭普通地址或伪造请求参数获得豁免。专用请求跳过 UA、地区、每日次数等风控规则，访问和次数照常登记，并显示专用链接白名单标记；不参与风险采样或多 IP 风险计算。同一客户的普通订阅地址继续按原规则检查，计数包含专用请求；不会将客户整体加入用户白名单、清除已有可疑标记或解除 Xboard 封禁。

每次打开导入页都会查询 Xboard 当前生成的完整地址，因此修改订阅域名后可继续使用同一个分享页。已导入应用的旧地址仍需重新导入。撤销会立即关闭导入页并取消该凭证的白名单资格；已导入应用的链接后续请求恢复普通风控检查，不删除应用配置、不重置订阅 Token。重新生成会得到新链接。链接持有人可以获取该客户的订阅，请只发给对应客户。

后台与采集插件都需更新为 **4.0.22**，先更新后台，再上传插件并按原部署方式重载 Xboard 工作进程。管理同步仍要求可访问的 Xboard HTTPS 根地址；客户订阅根地址继续支持 HTTP / HTTPS。本功能不在管理员用户列表加载时逐客户查询，不修改 Xboard 核心用户表。页面禁用缓存、外部资源与 Referer，后台加密保存随机分享凭证；服务端仍可能按自身配置记录访问 URL。
## v4.0.23 · 客户导入页只保留导入按钮

客户的 Shadowrocket 导入页移除“复制订阅地址”和“查看当前订阅地址”，只保留“导入到 Shadowrocket”按钮。无法打开时提示确认应用已安装并改用 Safari。微信／QQ 内仍提示换浏览器并可复制分享页链接；后台管理员的复制订阅、复制分享链接及撤销功能保持可用。专用白名单、访问计数、长期有效和手动撤销规则不变。本次仅调整后台页面，现有4.0.22采集插件继续兼容；尚未升级到4.0.22的插件仍需更新以支持专用白名单。新安装包版本统一4.0.23。
