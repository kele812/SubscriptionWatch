# v3.6 备份和恢复

## 网页下载

登录后进入「账号安全 → 下载完整备份」。压缩包包含 SQLite 一致性快照、master.key、已安装的 City/ASN 库及校验清单。含账号密码哈希、采集/TG/MaxMind 密钥，请私下保存。未登录不能下载。

下载采用流式压缩，但服务器须有足够空间暂存数据库与IP库的完整副本。备份期间不能修改或安装IP库；正常采集继续。反代如对大文件超时，适当提高该站点 proxy_read_timeout（例如600秒）。备份完成或失败后自动清理临时副本；进程被强制终止时可能残留 .backup-* 目录，确认没有备份运行后再人工清理。

## 网页直接导入（推荐）

1. 在目标风控后台登录，进入「账号安全」。新安装时先创建一个临时登录账号，导入后会替换为备份账号。
2. 选择本系统导出的完整tar.gz，点击「导入备份」并确认。此操作覆盖全部账号、面板和记录，不是合并数据。
3. 等待上传、文件/数据库/密钥校验和恢复。成功自动返回登录页，用备份内的账号密码登录即可，无需手动重启Docker。

网页压缩包上限2GB；服务器要有解压空间。只允许已登录管理员操作，校验失败不覆盖数据，替换失败会回滚，原文件保留。上传和校验时继续处理采集，实际替换时新请求返回短暂503，插件保留缓冲后重试。

宝塔如返回413，请在该站点设置合适的client_max_body_size，例如2048m；大备份还需提高client_body_timeout及proxy_read_timeout，例如900s。Cloudflare等上游可能有更小的上传限制，以实际服务设置为准；超过限制可使用下面的VPS工具。请勿把备份放到公开网站目录。

成功导入会退出所有旧会话、关闭自动封禁、取消旧任务及清空未发通知；数据、密钥和风险历史保留。确认采集插件重新连接后再按需打开自动封禁。

## VPS工具恢复（大文件或应急）

先准备好 v3.6 程序与 Docker，把备份上传到 /opt/watch-backups/backup.tar.gz。目录和文件必须允许容器内 node 用户读取。以下命令在含 compose.yaml 的程序目录执行：停止风控服务，构建镜像，启动一个只负责恢复的临时容器，最后启动后台。

```bash
cd /opt/SubscriptionWatch
docker compose stop watch
docker compose build watch
docker compose run --rm --no-deps -v /opt/watch-backups:/backup:ro watch node restore.mjs /backup/backup.tar.gz /data --service-stopped
docker compose up -d watch
docker compose logs --tail=60 watch
```

恢复命令校验路径、文件类型、SHA256、数据库和密钥后才替换数据。原数据移入 /data/restore-previous-时间戳；正常失败时回滚。恢复时不能有其他容器或进程同时读写该数据卷；--service-stopped 是操作者确认停机，脚本不能替你检测所有实例。恢复期间不要关机。

恢复保留账号、面板、规则、密钥、访问及风险历史；自动封禁强制关闭，旧待执行任务取消，旧通知队列与短期确认码清空，插件连接状态重置。不会自动解封 Xboard 用户。确认插件重新连接后再按需开启封禁。

如旧风控机仍运行，迁移前停掉旧实例，避免同一机器人多处轮询和重复控制。保持域名不变时修改DNS指向新机；换域名则在每个Xboard插件中更新风控地址，标识和密钥沿用恢复后的原值。新加坡反代通常不用改。Telegram 是否可用取决于新机出站网络。

## 验收与回退

用原账号密码登录，核对面板、历史、IP库和采集连接，再验证TG。确认恢复成功前不要删除 restore-previous-*。如需回退，停止服务，先另存当前完整数据，再将上述旧目录中的原文件移回 /data 根目录；恢复的数据库必须与同一备份里的 master.key 配套。

网页与VPS工具接受 v3.5/v3.6 网页生成的完整备份格式，不导入任意 tar.gz 或旧数据库裸文件。
