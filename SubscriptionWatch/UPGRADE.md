# 升级到 v3.7.0

本次只需升级风控后台，已有v3.5插件不必更新，新加坡反代不用改。无需填写 Xboard 地址、管理路径或 Authorization。

## 1. 风控机备份

将 SubscriptionWatch-v3.7.0.zip 解压到 /opt/watch-v3.7.0/SubscriptionWatch，保留旧代码。以下命令停止风控后台并复制完整数据，不停止 Xboard；旧目录不同请替换第一行。

```bash
cd /opt/SubscriptionWatch
docker compose stop watch
backup_dir="/opt/subscriptionwatch-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
docker compose cp watch:/data "$backup_dir/data"
```

确认备份成功再继续。备份包含数据库和加密密钥，不可公开。

## 2. 启动新版后台

以下命令构建启动新版、检查容器、健康接口及日志。

```bash
cd /opt/watch-v3.7.0/SubscriptionWatch
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:18080/healthz
docker compose logs --tail=100 watch
```

项目名仍为 subscriptionwatch-v2，沿用旧数据卷。不要修改项目名或执行 docker compose down -v。日志应显示 Subscription Watch v3.7.0 ready，健康接口返回 {"ok":true}。宝塔继续代理到 18080，网站绕过缓存。

原账号、面板、采集密钥、TG 配置和历史保留。从v3.3首次迁移关闭旧自动封禁开关并清除旧管理 API 凭据；从v3.4升级保留开关，新增观察期默认30分钟，保留封禁历史；旧未完成任务需核对。先升级后台可停止旧 API 封禁逻辑。

## 3. 核对 Xboard 插件（已有v3.5无需操作）

通过 Xboard 插件管理上传 SubscriptionWatchCollector-v3.5.0.zip 更新原插件。提前记下配置，更新后核对风控 HTTPS 根地址、面板标识、采集密钥和可信代理 IP，沿用原值并启用。

沿用已有每分钟 Laravel scheduler，不重复添加计划任务。Octane 按现有部署方式重载以加载新代码。不需要修改核心文件或数据库结构。

实际执行封禁会修改目标用户 banned 状态并清理登录会话；普通采集不写用户业务表。风险计算、IP 查询、历史及 TG 仍由风控机处理。

## 4. 验收

刷新页面，必要时 Ctrl+F5。自动封禁设置不再显示三个管理 API 输入框。等待约 1～2 分钟看到插件通道已连接，再按需开启开关。v3.0插件只能采集；v3.4可继续封禁但不支持手动解封，请更新v3.5。

先用测试账号核对订阅记录。开启封禁会在观察期满足后处理当前及后续高风险账号，请先检查当前列表。白名单、管理员、员工及邮箱不匹配用户受到保护。

任务有效期 30 秒，只下发一次。关闭开关不撤回已下发任务；风险解除或白名单不自动解封。显示“失败或待核对”时人工核对 Xboard，系统不自动重发该任务。

本地 Node 回归和模拟 Xboard/Redis/HTTP 的 PHP 执行测试通过；真实 Xboard、Octane、Redis 和 Docker 环境尚未集成验证。
