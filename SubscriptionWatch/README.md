# SubscriptionWatch v4.0.19

每个面板的“插件接入”可保存最多5个指向同一风控机的 HTTPS 地址，按优先顺序排列。保存后，还需在 Xboard 采集插件中用英文逗号填写同一组地址，并在 XBnpp 节点上配置备用地址。连接失败、超时或服务器5xx时才切换；认证失败、签名错误不切换。所有地址不可用时，由插件的“风控后台失联时继续下发”开关决定是否下发，默认关闭（拒绝）。

## 上传插件

后台和采集插件统一为 **v4.0.19**。下载 [后台 ZIP](https://github.com/kele812/SubscriptionWatch/raw/refs/heads/main/downloads/SubscriptionWatch-v4.0.19.zip) 和 [采集插件 ZIP](https://github.com/kele812/SubscriptionWatch/raw/refs/heads/main/downloads/SubscriptionWatchCollector-v4.0.19.zip)。先更新风控后台，再在 Xboard 插件管理上传新版插件并启用。访问记录同时展示“结果”（这次请求）和“当前状态”（该用户现在是否可疑、是否达到24小时请求上限，以及已计入次数和下一次序号）；本次请求通过 IP／域名白名单订阅时，列表和详情会单独标注，当前状态仍显示近24小时白名单次数。升级时能从留存的审核结果补标旧记录；找不到审核结果的旧记录不猜测。可在该行单独重置用户24小时计数，访问历史和可疑标记保留。同一次请求会检查完所有适用规则，访问详情逐条列出本次拦截原因；用户及 IP／域名白名单仍优先豁免所有规则；Cloudflare 豁免按下述新范围执行。

访问记录的“结果”栏已加宽：规则拦截时逐条列出命中规则；请求失败时显示能确认的原因。新版插件会用固定类别上报风控审核失联、响应校验失败等插件拒绝原因，不上传错误正文。其他失败只按响应状态、内容类型和是否返回订阅解释；若证据不足，则明确显示“具体原因未记录”。旧记录不会被推断为某种插件故障。

风险规则按面板新增“可疑用户禁止获取订阅”开关，默认开启；关闭只放行已有可疑标记这一项，其余规则照常执行。后台“访问记录”已更名为“获取订阅记录”。风险规则有独立菜单。可按面板开启“仅允许中国大陆或白名单 IP 获取订阅”；白名单支持 IP、域名和备注，域名解析失败时不匹配。严格执行地域限制时，插件的“风控后台失联时继续下发”须保持关闭。用户白名单或 IP／域名白名单命中后，跳过所有订阅风控规则，包括每日次数和已有可疑标记；访问仍记录。未命中白名单的大陆来源仍按其他规则检查。非指定客户端只拦截本次订阅，不标记可疑；多个中国大陆或非中国大陆 IP 在达到阈值的当次标记并跳转；云服务器 IP 每次请求都跳转，60 分钟第 3 次或 720 分钟第 10 次标记可疑。黑名单命中可选择启用拦截。每个用户滚动 24 小时默认最多请求 30 次，第 31 次起跳转，成功和拦截都计数；上限本身不标记可疑。手动取消可疑标记后，该用户每日次数从零重新计算，旧访问记录保留。风控后台失联或审核超时时，插件默认拒绝本次订阅；手动开启失联放行后才继续下发。后台明确拒绝、密钥错误或验签失败始终拒绝。

先在风控后台添加面板，再把风控 HTTPS 地址、面板标识和采集密钥填入插件。可信代理 IP 只填写你实际使用的反代 IP；Xboard 原有的每分钟计划任务需正常运行。

要区分客户来源 IP 与经过的反代，在每台反代的 Nginx `location /` 内覆盖这两个请求头，并填写该反代自己的公网 IP 和名称：

```nginx
proxy_set_header X-Watch-Proxy-IP "反代公网IP";
proxy_set_header X-Watch-Proxy-Name "自定义反代名称";
```

插件只在该 IP 确实出现在本次请求的可信转发链中时记录反代名称。直连或链路未核对成功时显示“未记录外部反代”；升级前的历史反代标识显示“未核实”。反代 IP 和名称由各台反代自行填写，不在程序中固定。

## 一键部署

在 Ubuntu 风控 VPS 上以 root 执行，先安装 Git、Docker 和 Docker Compose。下面命令下载代码、构建并启动服务，目标目录需尚不存在：

```bash
git clone https://github.com/kele812/SubscriptionWatch.git /opt/SubscriptionWatch-repo && bash /opt/SubscriptionWatch-repo/deploy.sh
```

## 一键更新

下载最新版、备份数据并重启风控后台：

```bash
bash /opt/SubscriptionWatch-repo/update.sh
```

原账号和数据保留，备份在 `/opt/SubscriptionWatch-backup-*`。采集插件需在 Xboard 单独上传更新。如果旧安装使用 SSH 下载，先执行：

```bash
git -C /opt/SubscriptionWatch-repo remote set-url origin https://github.com/kele812/SubscriptionWatch.git
```

## 宝塔反代

1. 将域名解析到风控 VPS，在宝塔添加此域名的网站。
2. 为网站申请 SSL，启用 HTTPS。
3. 添加反向代理，目标地址填 `http://127.0.0.1:18080`，关闭代理缓存。
4. 浏览器打开 `https://你的域名`，首次访问创建账号密码，再添加 Xboard 面板并配置插件。


## 4.0.16 Cloudflare 豁免调整

开启 Cloudflare 豁免后，仅对客户来源 IP 归属机构为 Cloudflare 的请求跳过地区限制、已有可疑标记、云服务器、黑名单及多 IP 阈值检查；仍执行已启用的 UA 检查和滚动24小时次数上限，成功与规则拦截均登记计数。已有可疑标记不被清除，历史记录不改写；网站套 Cloudflare 不等于客户 IP 命中豁免。用户及 IP／域名白名单仍优先豁免所有规则。



## 4.0.19 指定订阅地址与本地同步

在左侧“修改订阅的用户”页面，先填写安装了插件的 Xboard HTTPS 根地址，点击“保存地址并立即同步”。风控服务器须能访问该地址；Cloudflare/WAF 不应向 /api/v1/guest/subscription-watch/origin-sync 和 origin-lookup 返回浏览器挑战。两端使用已有采集密钥验签，不需要远程 MySQL 密码。

输入完整客户 ID 或邮箱点击搜索，显示 Xboard 当前生成的完整订阅地址，并可直接修改。链接包含客户 Token，仅在已登录管理页面按需返回，不保存到风控数据库、采集或诊断日志。自动刷新和读取已修改列表不会远程查询客户。主题需读取标准 subscribe_url，无需修改复制按钮。

搜索后修改与手动新增共用一条设置：同面板同客户 ID 以最后一次保存为准，搜索本身不修改。已采集邮箱须匹配。备选地址按面板独立保存，最多20个；编辑时可选择或手输。单独的“已修改用户”列表保留客户、指定域名、同步状态和修改时间，支持编辑和删除。

保存或删除会立即发签名通知。插件拉取分页快照，事务写入 Xboard 本地 subscription_watch_origins、subscription_watch_origin_state 独立表，再返回签名确认。显示“已同步到 Xboard”才表示已确认；失败时显示待同步，风控保留新设置，Xboard保留最近完整配置，每分钟任务补同步。未配置 Xboard 地址时仅定时同步，搜索不可用。同步不是无等待的保证，主动通知超时后仍可能由后续调度完成。

生成链接只读本地数据，同一请求一次映射查询，无逐客户远程地址请求。以本地用户ID、邮箱匹配当前Token，只替换根地址并保留路径参数。首次同步前或本地表不可读时使用站点默认地址；风控失联后保留最近同步地址。实际客户端订阅请求的风控审核和失联策略不变。

删除从已修改列表移除，同步成功后清除本地设置、恢复默认，不删除客户或备选地址。删除同步失败时旧映射暂存，可点击“保存地址并立即同步”重试。旧版已恢复默认记录也能删除。

先升级后台，再上传启用4.0.19插件，在 Xboard 自己的 Compose 项目目录执行 docker compose restart，使常驻进程加载新插件和路由。配置 Xboard 地址并同步，原指定客户自动迁入，无需重加。同步后刷新Xboard管理员或客户页面再复制／导入；客户端旧链接需重新导入。指定域名仍需提前配置同一Xboard的DNS、HTTPS、反代。不要回退旧插件，否则恢复逐客户网络查询。本次未连接你的线上Xboard，不保证其他原因的卡顿同时消失。
