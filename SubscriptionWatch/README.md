# 订阅观察 v3.7.0

独立 Docker 风控后台，配合 Xboard 轻量采集插件。单账号管理多个面板，各面板的数据和规则独立。赛博朋克深色界面，必须登录才能打开后台。

## 三台机器

| 机器 | 工作 |
|---|---|
| 风控 VPS | 运行本后台，保存记录、分析风险、查询本地 IP 库、处理 TG |
| Xboard VPS | 安装采集插件、Redis 临时缓冲、定时上报和可选封禁/手动解封 |
| 新加坡反代 VPS | 保持原先直接转发 Xboard，不转发到风控机 |

Xboard 不执行风险分析、IP查询或TG请求。采集仍有少量开销；网络上报在 scheduler 执行，不在客户订阅请求里等待。插件不修改核心代码，不创建访问日志业务表；安装状态和配置由 Xboard 自身正常保存。

## 全新安装

已有 v2 数据请先阅读 [UPGRADE.md](UPGRADE.md)，不要当成全新安装。

1. 把 `SubscriptionWatch-v3.7.0.zip` 上传到风控机，解压后确保 `/opt/SubscriptionWatch/compose.yaml` 存在。
2. 在风控机执行。第一条进入项目；第二条构建并启动；后两条检查状态：

```bash
cd /opt/SubscriptionWatch
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:18080/healthz
```

健康检查应返回 `{"ok":true}`。默认保留 Compose 项目名 `subscriptionwatch-v2`，用于平滑沿用 v2 数据卷；名称不是应用版本。程序版本为3.7.0。

3. 风控机宝塔添加域名，启用有效 HTTPS，反向代理到 `http://127.0.0.1:18080`，关闭缓存。无需公网放行18080。
4. 打开 HTTPS 域名，首次设置唯一登录账号、密码和确认密码。无安装验证码、无自定义后缀、无公开注册；账号3～64位，密码12～256位。
5. 以后直接在域名首页输入账号密码登录。“账号安全”可修改密码，修改后所有旧会话失效。
6. 点击“添加面板”。每个面板独立生成面板标识和采集密钥；在“面板设置”复制。

## Xboard 插件

Xboard 后台 → 插件管理 → 上传 `SubscriptionWatchCollector-v3.5.0.zip` → 安装并启用。

| 配置 | 内容 |
|---|---|
| 风控后台地址 | `https://你的风控域名`，不带管理员路径或 `/api` |
| 面板标识 | 从对应面板设置复制 |
| 采集密钥 | 从对应面板设置复制，不是管理员密码 |
| 可信代理IP | 你的现有链路使用 `203.0.113.10,127.0.0.1`；其他用户按自己的实际代理链填写 |
| 临时队列上限 | 默认2000 |
| 临时有效期 | 默认3600秒 |

每个 Xboard 使用自己的标识和密钥。已有 Laravel scheduler 必须正常工作，不要重复增加 cron。常驻 Octane 若未加载新插件，按原部署方式重载。用测试账号更新订阅，等待1～2分钟查看最近上报时间和访问记录。

常规采集不需要管理 API Authorization、用户全量同步或订阅路径配置。封禁由v3.4插件领取签名任务执行，也不需要管理API凭据。Xboard用户ID和邮箱来自当前已认证订阅请求。无效Token在进入采集钩子前被拒绝，不能记录。UA可以伪造；客户用代理时看到的是出口IP。

## 风险规则（v3.7）

每个面板独立配置，7条基础规则加组合升级。下面为默认值，现有面板的原参数保留；新增规则按默认值开启。修改时动态显示触发条件，保存才生效。

|规则|统计范围和阈值|等级|
|---|---|---|
|使用非指定客户端获取订阅|24小时内存在不匹配或空UA|低|
|多个IP获取同一订阅|24小时5个不同IP|中|
|频繁获取同一订阅|60分钟5次有效获取|中|
|短时间内多个国内IP获取订阅|10分钟3个不同国内IP|中|
|多个云服务器IP获取订阅|10分钟3个不同云服务器IP|中|
|多个IP和不同UA同时获取订阅|同一10分钟内3个IP且3种完整UA|高|
|短时间跨多个国家或地区获取订阅|30分钟3个国家或地区代码|低|

组合升级默认10分钟：开启频率规则，并开启国内IP或云服务器IP规则时，用同一10分钟内的成功请求重新计算，各自达到数量阈值才升级高风险。普通IP和国内IP不作为两个独立条件叠加。组合窗口可修改。

除UA异常检查外，仅统计HTTP 2xx请求。这是依据插件上报状态的近似成功定义，不检查订阅正文；HTTP 304、错误和未知状态不计。无效Token若未进入插件采集钩子，则无法记录。

国内同IP且完整原始UA完全相同，在频率窗口内合并为1次；国外/未知IP逐次计算。完整UA按原文区分，版本号、大小写不同算不同UA；允许关键词仍按不区分大小写的包含匹配。空UA也算一种原始值。

用户白名单免除全部规则，必须与已采集用户ID、邮箱准确对应，未知用户不能添加。IP白名单及开启的Cloudflare组织豁免排除对应请求，其他IP正常检查。自有节点不计入国内IP、云服务器IP、跨国家规则，但仍参与普通IP、UA、频率、IP与UA双条件；组合内的国内/云服务器部分排除自有节点。

影响预览只读取现有评估样本，显示低、中、高风险人数，不保存、不发通知、不操作封禁。样本最多7天，已手动处理记录不参与；不能代替对未来流量的判断。保存会重新评估已有样本，并可能通知及进入已开启的封禁观察期。

详情首框按IP和完整UA展示触发证据、归属、时间、相关规则；每条原因最多100组IP/UA，超出明确提示。分组展示最近一次，不代表只有一次请求。历史保存当时的规则版本、阈值、关键词和证据，不随未来配置变化而覆盖。旧版历史不补造证据；旧版风险等级按当时版本解释。

自动封禁默认关闭，开启后默认持续高风险观察30分钟。风险消失或降级取消观察，风险解除不会自动解封。管理员/员工保护、白名单和任务签名机制保持有效。

手动取消风险后旧样本不再触发，新异常可以重新标记；后台每分钟检查条件到期。

## 三种独立数据清理

- 清空访问历史：只删除该面板原始访问列表。风险用户、白名单、评估历史继续保留。用于滚动评估的短期证据（时间/IP/UA）最长7天自动清理，所以清空访问历史不会立即解除风险。SQLite释放的页用于后续写入，不承诺立刻缩小磁盘文件。
- 删除风险用户记录：独立操作；同时把旧请求设为已处理，新增异常可重新生成风险用户。评估历史仍保留。
- 删除评估历史：可逐条或整面板清空；不改变当前风险状态。

删除整个面板会删除该面板所有数据、配置、风险和通知任务，需要输入面板名称和当前登录密码。CSV单次最多5万条，可按时间分段。访问历史默认长期保留，可设置保留天数；评估历史保持独立长期保留。80GB仍需关注容量。

## 账号与登录

只有一个登录账号，没有注册开关、管理员入口或账号管理页。未登录只返回登录页；后台HTML、业务接口和应用脚本都需要有效会话。页面禁止缓存，退出或改密使旧会话失效。宝塔必须关闭此站点的代理缓存。

升级时保留最早的原管理员账号和密码，原普通账号停用，其面板统一归入保留账号，历史数据和采集密钥保留。请先备份完整数据卷。

## Telegram（每个面板一个机器人，仅私聊）

1. 先在顶部选择要配置的面板，再从 BotFather 创建独立机器人，将 Token 填入“TG机器人”。不同面板必须使用不同机器人，但可以绑定同一个Telegram私聊用户；已有Webhook的机器人需先自行停用原Webhook或换新机器人。
2. 先用你的Telegram个人账号向机器人私聊发送 `/start`。在页面填写 Token 和个人数字ID，点击保存并验证；无需绑定码。不是 @用户名或群组ID。
3. 只接受所填数字ID的本人私聊和按钮操作，不接受群聊。保存前核对 getChat 返回的私聊ID，验证失败不会覆盖原配置。更换个人ID需重新填写Token并保存。
4. 机器人自动对应配置面板，不能切换到其他面板。`/risk` 查看风险，`/user 用户ID` 查看近期统计，`/resolve 用户ID` 发出取消确认按钮，`/help` 查看说明。
5. 每个面板可关闭TG风险通知。同一持续风险不会因计数增加反复通知；新增风险原因或取消后重新触发会通知。失败会退避重试，通知积压最长7天。Telegram无法提供端到端去重，发送成功但响应丢失时可能重复。

机器人由风控机调用Telegram API，无需配置Webhook或新增公网端口。账号Token加密存储。未绑定私聊前不补发历史通知。

## IP数据库（仅手动更新）

在“系统设置”导入 MaxMind 提供的 GeoIP.conf，或手动填写数字 Account ID 和完整 License Key。导入仅解析并加密保存凭据，不自动下载；接着点击“检查更新”，再点击“下载并安装”。文件需包含 GeoLite2-City 和 GeoLite2-ASN，额外的 Country 不下载。

HTTP 401 表示下载认证未通过：检查数字账号ID与完整密钥是否来自同一账号、密钥是否已撤销或复制不完整。配置格式正确不能保证授权有效。本项目未用你的真实密钥执行下载。

City提供国家/地区、城市；ASN提供网络所属组织，不保证等同实际宽带运营商。使用本地MMDB查询并缓存，所有面板共用。无数据库或字段缺失显示未知，本机/内网单独标注。中国大陆多IP规则使用国家代码CN；数据中心规则和Cloudflare豁免使用ASN组织名。数据库缺失或无法识别时，相应地域/组织规则不会触发，也不会给予Cloudflare豁免。

后台从官方固定地址下载，验证SHA-256、解压限制及数据库类型，两份都成功后才切换。成功后删除压缩包、临时目录和旧库；失败继续使用旧库。没有自动更新开关，没有定时下载任务。建议预留500MB用于替换；数据库本身约数十MB，大小以发布版本为准。

## 备份与限制

备份风控数据卷全部内容，尤其 `master.key`、`watch.sqlite`、WAL及geo目录。维护窗口停止风控容器后复制数据，再启动。不单独复制正在运行的SQLite主文件。风控短时停止不影响订阅，但插件超过缓冲上限或有效期会丢记录。

2核2GB为目标环境，Compose限制768MB内存、1.5核CPU；实际可承载量取决于面板数、请求量和历史体积，不承诺无限容量或零丢失。插件默认最多300条/分钟；持续更高流量需要调优。所有分析在风控机，不会因打开后台或查询归属地额外查询Xboard用户表。

验证范围见 [TESTING.md](TESTING.md)。正式启用前先验证你的Xboard版本、Docker构建、实际IP、真实TG连接和MaxMind下载授权。

升级至v3.2时，原机器人优先分配给此前选中的面板；未选中时分配给该账号第一个面板，保留Token和私聊绑定。其余面板单独配置新机器人。旧确认按钮失效，需重新发送指令；其他面板的旧待发送通知不转发。无面板的旧配置保存在迁移备份表中，不自动启用。

## v3.3 新规则与修复

- 白名单列表仅显示主动添加的用户。添加时精确核对已采集ID与邮箱，未知用户拒绝；插件上报邮箱变化时自动撤销旧豁免。升级时无法用历史访问验证的旧白名单将撤销，需用户重新获取订阅后添加。
- 低风险：仅UA异常。中风险：普通IP数量或请求频率超限。高风险：默认10分钟内3个不同中国大陆IP，或3个不同数据中心IP；单家或多家数据中心均计数。时间和数量可改，关键词可添加。多条件同时命中取最高等级。
- Cloudflare豁免默认关闭，按organization包含完整Cloudflare词匹配；IP白名单支持完整IPv4/IPv6，不支持CIDR。豁免的请求继续保存，但不计入风险，不豁免同用户其他地址。用户白名单则豁免整个用户。
- 数据中心IP不等于恶意访问，代理出口也可能属于云厂商；建议先观察高风险记录再开启自动封禁。
- 自动清理：保留天数0为关闭，设置1～3650后每分钟删除超期访问。手动清空仅点击确认，无密码和确认文字；仍须登录。风险用户、评估历史及白名单不删，短期评估证据按原窗口保留。
- 访问详情显示原始UA，不做客户端推测。
- 修复TG超时异常的数字错误码导致错误处理再次抛错的问题；超时返回明确提示，不中断服务。反代返回HTML时显示HTTP状态，避免原始JSON解析错误。

## 可选：由插件执行高风险账号封禁

后台与插件均更新为v3.4，仍使用已有风控HTTPS地址、面板标识及采集密钥。无需Xboard地址、管理路径或Authorization。升级首次自动关闭旧封禁开关并清除旧API凭据，保留执行历史。插件连接后再手动开启开关。

插件通过现有每分钟scheduler轮询控制通道，每次最多3个任务。请求和响应分别签名，响应绑定本次随机nonce和面板标识；任务30秒有效。后台领取前重新评估风险和白名单。插件接受封禁动作，v3.5插件还支持手动解封，执行前检查期限、用户ID、邮箱及管理员/员工身份，事务内设置banned=1并调用Xboard会话清理服务，不改数据库结构或Xboard核心文件。失败回滚，其他用户字段保持原值。

任务持久化且只下发一次；传输丢失或执行中断标为“失败或待核对”，不重复封禁。插件将执行结果暂存在独立Redis命名空间，最多100条、7天，重传直到后台确认。Redis不可用时不执行，风险分析继续在风控机。结果丢失时请人工核对Xboard状态。

关闭开关不会撤回已下发的任务；最长30秒内可能仍执行。风险解除、白名单豁免或关闭开关不会自动解封已经被封禁的账号。插件旧版只能采集，不能领取封禁任务。

## v3.5 七项优化

1. 面板设置新增自有节点出口IP，排除中国和数据中心IP计数，仍评估UA、普通IP数和频率；普通IP白名单保持完全豁免。支持完整IPv4/IPv6，每个面板独立。
2. 风险详情展示窗口、阈值、实际数量、IP归属/组织、原始UA、自有节点标记。每条规则最多保存30条证据并标注截断；历史不会因删除访问记录而消失，旧历史不伪造证据。
3. 封禁前默认持续高风险观察30分钟，可设0～10080分钟；降级/解除重置，保存封禁配置重计时。到期后重新验证风险及白名单才派发任务。
4. 手动解封独立入口，核对已采集ID和邮箱，需v3.5插件；管理员/员工受保护，支持幂等回执。提交和成功回执会清除已处理风险证据，新异常可重新标记；未知解封结果期间暂不自动封禁该用户，请人工核对后重新提交解封以取得明确结果。
5. 健康状态区分未上报、正常、积压与超过3分钟中断；显示插件版本、最近上报、失败/丢弃/过期数。失败数须插件v3.5；旧版显示未知，离线不能获取实时计数，Redis计数7天过期或重启丢失时可能归零。
6. 同一用户未发风险通知合并，连续同等级异常不重复提醒，升级再提醒；封禁/解封成功、失败或超时单独通知。网络失败仍退避重试，不解决VPS无法连接Telegram的线路问题。
7. 账号安全中一键下载一致性备份，包括数据库、密钥和已安装IP库；可网页导入恢复，也保留VPS停机恢复工具；校验失败不覆盖原数据，恢复后关闭自动封禁及取消旧任务。见 BACKUP.md。

从v3.4升级请同时更新后台与插件，原有配置保留；自动封禁原开关保留但新增观察期默认30分钟，升级不会立即追补旧观察时间。v3.4插件仍可采集和封禁，手动解封与失败计数需要v3.5。
